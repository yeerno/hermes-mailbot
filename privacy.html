Privacy Policy

HermsAgent — last updated 14 November 2026

HermsAgent is a single-user, self-hosted assistant. This policy explains what data it accesses, why, and what happens to that data.

1. Data accessed

With the account owner's explicit consent, HermsAgent accesses Gmail messages belonging to that same account, using the scope https://www.googleapis.com/auth/gmail.readonly. It may read message headers, bodies, attachments the owner explicitly asks about, and labels. No other Google service is accessed.

2. Purpose

The data is used solely to serve the account owner: searching their mailbox and producing summaries of messages they ask about. There is no other purpose.

3. Storage

An OAuth refresh token is stored locally on the owner's own machine so the connection survives restarts. Message content is processed in memory for the duration of a request. Message bodies are not retained in a database, are not uploaded to third-party analytics or advertising services, and are not used to train models.

4. Sharing

Data is not sold, rented, transferred or disclosed to any third party, except where strictly necessary to operate the assistant's language-model backend — in which case only the text needed to answer the owner's request is sent, and only at the owner's initiation. No data is shared for advertising, creditworthiness, or lending purposes.

5. Google API Services User Data Policy — Limited Use

HermsAgent's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Specifically:

  • Data is used only to provide or improve the user-facing features that are prominent in this application's user interface.
  • Data is not transferred to others except as necessary to provide those features, to comply with applicable law, or as part of a merger or acquisition with prior user consent.
  • Data is not used for serving advertisements, including personalised or interest-based advertising.
  • Data is not used to determine creditworthiness or for lending purposes.
  • No humans read the data, except with the owner's affirmative consent for specific messages, for security purposes, or to comply with law.

6. Security

Access is limited to the read-only Gmail scope, so the application cannot send, delete, or modify mail even if its credentials were misused. Tokens are stored with owner-only file permissions on the owner's machine and can be revoked at any time at myaccount.google.com/permissions.

7. Retention and deletion

The owner can revoke access at any time from their Google Account permissions page, which immediately invalidates the stored token. Deleting the local token file removes all locally stored credentials. Because message bodies are not persisted, revoking access leaves no retained mail content behind.

8. Children

The application is not directed to children under 13 and is used by a single adult account owner only.

9. Changes

Material changes to this policy will be reflected in the "last updated" date above, on this page.
